# CCI Admin UI

Shared React components, styles and API adapters for Cool Cat Ideas products.
Both editions of each product consume the same versioned packages. Each product bundles
its dependencies into its own assets; site owners do not install this repository.

| Package | Purpose |
| --- | --- |
| `@cci/admin-ui` | React components and product themes |
| `@cci/admin-theme` | Tailwind tokens, shared styles and runtime class lists |
| `@cci/admin-core` | API transport and response normalization |
| `@cci/wp-adapter` | WordPress API adapter |
| `@cci/presta-adapter` | PrestaShop API adapter |

License status components display data and invoke callbacks supplied by a
product. They do not authorize premium operations. License verification,
signing keys and premium feature implementations are outside this repository.

## Use in products

Products pin release archive URLs and their integrity hashes in npm lockfiles.
A released product builds with `npm ci` and its normal build command, without
cloning this repository or accessing a private framework.

After [installing the packages and configuring the shared styles](docs/1.0.0/en/installation.md),
import the entry point for your product. For example, a Blog editor action can
use the shared button:

```jsx
import { Button } from '@cci/admin-ui/blog';

export function SaveAction({ onSave, saving = false }) {
  return (
    <Button variant="save" disabled={saving} onClick={onSave}>
      {saving ? 'Saving…' : 'Save changes'}
    </Button>
  );
}
```

The product supplies the save handler and state. The component supplies the
button appearance and interaction styles. Styles must be generated by the
product build; importing a React component alone does not load the stylesheet.

The theme's `addon-safelist.cjs` lists utility classes supported by carousel
add-on panels. Extend that style contract when introducing a new add-on layout.
Base-edition builds must not scan private Pro repositories for CSS classes.

### Administration layout

Use `AdminShell` and `AdminWorkspace` from `@cci/admin-ui/layout` for product
navigation and content. Import `@cci/admin-ui/src/admin-layout.css` before
Tailwind in the product stylesheet. Keep the sidebar as the shell's first child;
its navigation area should scroll when its contents exceed the available height.

Above 960 px, the shell measures the space below the host page header and uses
it as the minimum page height. Longer lists, sidebars and editors extend the
page and use normal browser scrolling. Pass the current section as
`AdminWorkspace`'s `scrollKey` to open a new section at the top without resetting
its form state. WordPress's footer and PrestaShop's bottom page padding are
omitted only on these product screens. Narrow screens keep normal page scrolling.

### Layout builder controls

`createBuilderComponents()` exposes the panel, header, heading, item, actions,
metric, grip and grid ruler used by Nice Menu and Product Inquiry. Import
`@cci/admin-ui/src/builder.css` before Tailwind in the admin stylesheet.
Selection belongs to the heading or item main button (`aria-pressed`). Keep the
grip inside that control and actions as siblings, so there are no nested buttons.
The shared stylesheet owns control spacing, typography, hover, focus, selection
and narrow column states. Product styles only arrange grid spans and domain content.

The field and menu item editors use the shared dialog frame. Pass the product
admin root as `portalContainer` to retain the product's CSS variables and native
admin resets. The frame manages focus, Escape and body scroll. Radix dropdowns
remain above the dialog and handle their own keyboard events.

## Build and contribute

Use Node.js 23.7 or later and npm 11.7 or later.

```sh
npm ci
npm test
npm run release
```

`npm run release` builds the packages and prepares `.tgz` archives, checksums and
`releases/packages.json`. The archives include compiled JavaScript and source.
The command creates local artifacts without publishing them.

See [Contribute and release](docs/1.0.0/en/contributing.md) for the local candidate
workflow, consumer verification and publication order. Products depend on the
matching public `.tgz` assets; GitHub source archives do not replace them.
Published package versions retain their original contents and checksums.

Submit shared UI changes here; product-specific behavior belongs in the product
repository.
